# Phase-2 Language Execution V1.1

V1.1 changes only language realization and independent semantic perception. The Action Contract, Probe eligibility, Redirect selector, structured plan, verifier comparison, one-repair bound, mapper, gameplay, and smoke gate remain unchanged.

## Public opportunity metadata

The perceiver receives generated text and `PublicLanguageContextV1`, never the requested plan. Its strict JSON response contains only the six language-derived fields: plural commitment targets, rejected targets, vote-intent targets and information requests, plus abstention and private-fact-claim flags. `speaker` and `phase` are **not** model response fields. After strict parsing, `parse_perceived_semantics(raw, public_context)` binds them from the trusted current public PRE context into `Phase2SpeechSemanticV1`. This prevents an addressed or promoted player from being mistaken for the speaker while retaining the verifier's opportunity check. `LANGUAGE_VERSION` is `phase2_speech_semantic_v1_1`; the audit record shape and `LANGUAGE_AUDIT_VERSION` are unchanged.

## Language semantics and realization

The perception prompt distinguishes a direct `CURRENT_SUSPICION_BASIS` question about the addressee's current suspicion/vote judgment and public reasons from an exile commitment. It states that “本轮投 X”, “本轮放逐 X”, “推动大家投 X”, “坚决处理 X”, and “坚决将放逐票投给/投向 X” express both a main target commitment and vote intent. Mere mention, comparison, or discussion of another player is not a rejection. Examples in the perception prompt use generic public text and contain no requested action or target from the plan. A narrow, plan-blind post-parse check adds these explicit request and vote cues when the model omits them, retains conflicting targets for verifier inspection, and removes unsupported multi-target rejection or abstention only when the actual text supplies no such expression. It does not alter the verifier.

For Push, the actor is told that the upstream plan has frozen the sole target and that the actor is not a target selector. It may use already public context to support that target, but must not switch targets, add another commitment or rejection, abstain, or ask an extra question. It is asked for one or two concise natural sentences, not a fixed output template. A repair prompt repeats the same complete action-specific requirements and preserves the original action, targets, and request. The verifier and one-repair policy remain unchanged, so target drift and unrequested abstention still fail.

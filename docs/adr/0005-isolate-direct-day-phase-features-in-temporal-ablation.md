# Isolate direct day and phase features in the temporal ablation

Implicit Temporal and Explicit Day/Phase consume exactly the same canonical public histories, including authoritative Phase Transition events, and share PRE boundaries, V1 annotations, belief targets, folds, initialization, optimizer, training protocol, and trainable parameter graph. The sole controlled difference is whether each structured token receives direct day and phase representations. A Phase Transition establishes and itself carries its new Public Temporal State; every subsequent structured token, including all tokens derived from one public speech, receives that state until the next transition. Propagation is strictly causal and never backfills from a future transition. Explicit uses a versioned, non-trainable 256-dimensional Deterministic Temporal Code: a 128-dimensional sinusoidal day subspace and a 128-dimensional non-ordinal, pairwise-orthogonal phase subspace are normalized to equal energy and combined at RMS `0.02`, then added to the structured token base embedding. Implicit adds zero at the identical injection point. Learned temporal embeddings, projections, gates, scales, compensated architectures, marker-only features, removed phase transitions, clipping or finite day vocabularies, and separate Dataset schemas are excluded.

The phase codebook is the analytic Walsh–Hadamard parity construction `P(r,c) = 0.02 * (-1)^popcount(r & c)` for coordinates `c=0..127`, with fixed phase rows `night→1`, `discussion→2`, `vote→3`, `pk_discussion→4`, and `pk_vote→5`. Its canonical serialization is a row-major C-contiguous `[5,128]` matrix of little-endian IEEE-754 float32 values, and provenance binds the vocabulary and order, row mapping, parity formula, amplitude, dimensionality, dtype, endianness, layout, and SHA-256 digest of the raw contiguous bytes. Runtime dtype or device conversion never changes that canonical digest, and unknown or missing phases fail closed.

The day half uses `D(day,2k)=sin(day/10000^(2k/128))` and `D(day,2k+1)=cos(day/10000^(2k/128))` for `k=0..63`, followed by one global fixed amplitude factor that gives every row RMS `0.02`; per-row normalization is forbidden. Before an experiment, the allowed development data determines `max_observed_day`, and a Canonical Day-Code Table containing rows `0..max_observed_day` is materialized as a row-major C-contiguous `[max_observed_day+1,128]` little-endian float32 artifact. Its metadata and SHA-256 bind the formula identity, temporal-code version, maximum day, shape, dtype, layout, and raw bytes. Downstream runs load and verify the immutable table rather than recomputing trigonometric values; an out-of-range day, digest mismatch, clipping, unknown bucket, fallback recomputation, or dynamic extension fails closed. A new dataset may explicitly publish a longer table under the same mathematical version but a new table digest.

The Temporal Evaluation Matrix has two training lineages, not four: Implicit Temporal Primary training and Explicit Day/Phase Primary training, both supervised only on eligible non-wolf observed rows. Each fold checkpoint is evaluated twice, once for Primary Development OOF and once for All-Alive Identifiability Stress, and both reports bind the identical checkpoint digest. Thus the temporal comparison changes only direct temporal information, while the within-checkpoint population comparison measures expansion to all alive observers; stress results cannot influence Primary training or selection.

The formal Primary Temporal Information Effect is paired within each held-out game: subtract Explicit Day/Phase Primary mean belief KL from Implicit Temporal Primary mean belief KL, then average those differences equally across games. Positive values mean direct temporal information reduced error; zero and negative values are retained. Uncertainty resamples game IDs and their implicit/explicit score pairs together in a paired game-cluster bootstrap. The lineages share the Development Publication, outer folds, Primary row identities, fixed training budget, model graph, initialization schedule, and evaluation contract, so direct temporal information is the only planned experimental difference. An All-Alive temporal contrast may be a secondary diagnostic, but it is not a second temporal headline, and Phase-1 defines no interaction headline.

For each outer fold, the Paired Initialization Contract requires both temporal lineages to load the exact same canonical initial trainable tensor bytes and bind the same `paired_initial_state_digest`. Optimizer initial state, game order, batch boundaries, augmentation and cyclic-rotation schedule, RNG and dropout schedule, and fixed optimizer-step budget are also paired. Explicit's deterministic temporal code and Implicit's zero code at the common injection point are the sole planned difference. Final checkpoints are expected to diverge, and cross-hardware bitwise training determinism is not required, but backend, software and runtime versions, and determinism settings remain provenance-bound.
